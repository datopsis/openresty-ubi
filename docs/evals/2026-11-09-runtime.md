## Cases and observed results

Each architecture runs the same cases under both Podman and Docker:

- UID 999:0 with explicit plaintext demo opt-out, and UID 12345:0 with a
  read-only mounted complete configuration: both serve real HTTP requests.
- Twenty consecutive `/lua` requests per identity/runtime return JSON from
  LuaJIT, CJSON and PCRE2 with the expected regex result and locked NGINX core
  version. **80 Lua requests per architecture, 160 total**, all pass.
- `/` serves the expected static page and nosniff header without a version in
  the server header; `/healthz` returns `ok`. Both pass for each identity.
- Every sampled `/proc/*/status` has the expected non-zero UIDs, zero effective,
  permitted and bounding capabilities, and NoNewPrivs=1. PID 1 is NGINX.
- Actual `/proc/mounts` shows root read-only and `/tmp` as
  rw/noexec/nosuid/nodev. Root writes fail. Executables/config are not writable.
- Only TCP 8080 listens. Package managers, OPM, compilers, downloaders,
  repository configs and public RPM key files are absent. No setuid/setgid
  files remain under executable directories. SIGQUIT exits with status zero.
- Missing configuration, missing writable mount, UID 0, absent config file,
  invalid config and empty config each exit non-zero with a useful diagnostic:
  **12 negative starts per architecture**, all pass.
- `openresty -v` matches locked 1.31.8.1. The live Lua-reported core matches
  locked NGINX 1.31.8.

The first CI run exposed a real root-owned `/tmp/openresty` directory copied
into Podman's tmpfs. Removing the build-time directory let the non-root
entrypoint create it. The same runtime test then passed without relaxing it.

Local namespace creation is forbidden (`cannot clone: Operation not permitted`),
so no local container-runtime success is claimed. Local lint, unit tests,
signature verification and real RPM negative tests passed. Neither CI platform
proves RHEL host, SELinux enforcing, OpenShift, SCAP, FIPS or STIG qualification.
